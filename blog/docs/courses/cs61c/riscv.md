# RISC-V

RISC-V 是一套开放、模块化的指令集架构。它把最小整数指令集作为基础，再按需叠加乘除法、原子操作、浮点、向量等扩展。本篇只讨论 CS61C 使用的 **RV32I**：整数寄存器宽度为 32 位、地址空间为 32 位，并实现基础整数指令集 `I`。

RISC-V 使用 load/store 架构：只有加载和存储指令访问内存，算术与逻辑指令只操作寄存器。基础指令通常编码为固定的 32 位，源寄存器、目的寄存器位于相对稳定的位置，便于硬件并行完成译码和寄存器读取。

## 寄存器

RV32I 有 32 个 32 位整数寄存器，编号为 `x0`～`x31`。`x0` 的值被硬件固定为 0：读取总是得到 0，写入结果会被丢弃。其余寄存器没有硬件层面的用途差异，但 ABI 为它们约定了名称和调用职责。

| 寄存器 | ABI 名称 | 用途 | 保存责任 |
| --- | --- | --- | --- |
| `x0` | `zero` | 常量 0 | — |
| `x1` | `ra` | 返回地址 | caller-saved |
| `x2` | `sp` | 栈指针 | callee-saved |
| `x3` | `gp` | 全局指针 | — |
| `x4` | `tp` | 线程指针 | — |
| `x5`～`x7` | `t0`～`t2` | 临时值 | caller-saved |
| `x8` | `s0` / `fp` | 保存寄存器或帧指针 | callee-saved |
| `x9` | `s1` | 保存寄存器 | callee-saved |
| `x10`～`x11` | `a0`～`a1` | 参数或返回值 | caller-saved |
| `x12`～`x17` | `a2`～`a7` | 参数 | caller-saved |
| `x18`～`x27` | `s2`～`s11` | 保存寄存器 | callee-saved |
| `x28`～`x31` | `t3`～`t6` | 临时值 | caller-saved |

caller-saved 寄存器可以被被调用函数随意覆盖，调用者若仍需其值，必须在调用前保存。callee-saved 寄存器则由被调用者负责在返回前恢复。`sp` 按 ABI 要求向低地址增长，并在函数调用边界保持对齐。

## 指令编码

RV32I 基础指令长度为 32 位，并按照用途组织为六种主要格式。`opcode` 决定大的指令类别，`funct3`、`funct7` 进一步区分操作。`rs1`、`rs2` 和 `rd` 在各格式中尽量保持固定位置。

### R 型

R 型用于两个寄存器源操作数的算术和逻辑运算。

```riscv-format
funct7:7 | rs2:5 | rs1:5 | funct3:3 | rd:5 | opcode:7
```

### I 型

I 型用于立即数运算、加载和 `jalr`。立即数 `imm[11:0]` 通常符号扩展到寄存器宽度。移位立即数指令复用其高位保存额外功能码。

```riscv-format
imm[11:0]:12 | rs1:5 | funct3:3 | rd:5 | opcode:7
```

### S 型

S 型用于存储。它没有 `rd`，因此把立即数拆到原来 `funct7` 和 `rd` 所在的位置。

```riscv-format
imm[11:5]:7 | rs2:5 | rs1:5 | funct3:3 | imm[4:0]:5 | opcode:7
```

### B 型

B 型用于条件分支。重组立即数后在最低位补 0，再进行符号扩展并加到当前 PC 上。编码将立即数位打散，是为了在保留寄存器字段位置的同时尽量复用 S 型数据通路。

```riscv-format
imm[12\|10:5]:7 | rs2:5 | rs1:5 | funct3:3 | imm[4:1\|11]:5 | opcode:7
```

### U 型

U 型为 `lui` 和 `auipc` 提供高 20 位立即数。`lui` 将其写入结果高位。`auipc` 则将该值加到当前 PC。

```riscv-format
imm[31:12]:20 | rd:5 | opcode:7
```

### J 型

J 型用于 `jal`。与 B 型类似，立即数最低位隐含为 0。重组并符号扩展后形成 PC-relative 跳转偏移。

```riscv-format
imm[20\|10:1\|11\|19:12]:20 | rd:5 | opcode:7
```

这些格式不是六套互不相关的布局：寄存器编号固定在少数位置，立即数的符号位总是位于指令的最高位 `31`，硬件可以尽早开始寄存器读取与符号扩展。B 型和 J 型看似反直觉的立即数排列，主要是在简化硬件布线与保持字段位置之间取舍。

## 基本指令

### 高位立即数

U 型指令使用 20 位立即数。汇编语法中的 `imm20` 对应结果的位 `31:12`。

| 指令 | 操作 | 说明 |
| --- | --- | --- |
| `lui rd, imm20` | `rd = imm20 << 12` | 装入高位立即数，结果低 12 位为 0 |
| `auipc rd, imm20` | `rd = pc + (imm20 << 12)` | 以当前指令地址为基准生成 PC-relative 地址 |

汇编器常用 `lui` 与 `addi` 构造任意 32 位常量。实际写代码时通常直接使用 `li` 伪指令。`auipc` 常与 `jalr` 或加载、存储指令配合，用于访问远距离的代码和数据。

### 整数计算

寄存器型指令写作 `op rd, rs1, rs2`。除移位外，立即数型指令写作 `op rd, rs1, imm`，其中 12 位立即数先符号扩展到 32 位。

| 立即数指令 | 操作 |
| --- | --- |
| `addi rd, rs1, imm` | 加法，`rd = rs1 + sign_extend(imm)` |
| `slti rd, rs1, imm` | 有符号小于时写入 1，否则写入 0 |
| `sltiu rd, rs1, imm` | 将符号扩展后的立即数按无符号数参与比较，小于时写入 1 |
| `xori rd, rs1, imm` | 按位异或 |
| `ori rd, rs1, imm` | 按位或 |
| `andi rd, rs1, imm` | 按位与 |
| `slli rd, rs1, shamt` | 逻辑左移 |
| `srli rd, rs1, shamt` | 逻辑右移，高位补 0 |
| `srai rd, rs1, shamt` | 算术右移，高位复制符号位 |

| 寄存器指令 | 操作 |
| --- | --- |
| `add rd, rs1, rs2` | 加法 |
| `sub rd, rs1, rs2` | 减法 |
| `sll rd, rs1, rs2` | 逻辑左移 |
| `slt rd, rs1, rs2` | 有符号小于时写入 1，否则写入 0 |
| `sltu rd, rs1, rs2` | 无符号小于时写入 1，否则写入 0 |
| `xor rd, rs1, rs2` | 按位异或 |
| `srl rd, rs1, rs2` | 逻辑右移，高位补 0 |
| `sra rd, rs1, rs2` | 算术右移，高位复制符号位 |
| `or rd, rs1, rs2` | 按位或 |
| `and rd, rs1, rs2` | 按位与 |

整数加减法按模 $2^{32}$ 截断，不设置溢出标志，也不会因有符号溢出而陷入异常。寄存器移位只读取 `rs2` 的低 5 位。立即数移位的 `shamt` 也是 5 位，因此有效移位量均为 0～31。

### 访存

RISC-V 使用按字节寻址的小端内存。访存操作数写作 `offset(base)`，有效地址为 `x[base] + sign_extend(offset)`。

| 加载指令 | 操作 |
| --- | --- |
| `lb rd, offset(rs1)` | 读取 8 位并符号扩展到 32 位 |
| `lh rd, offset(rs1)` | 读取 16 位并符号扩展到 32 位 |
| `lw rd, offset(rs1)` | 读取 32 位 |
| `lbu rd, offset(rs1)` | 读取 8 位并零扩展到 32 位 |
| `lhu rd, offset(rs1)` | 读取 16 位并零扩展到 32 位 |

| 存储指令 | 操作 |
| --- | --- |
| `sb rs2, offset(rs1)` | 写入 `rs2` 的低 8 位 |
| `sh rs2, offset(rs1)` | 写入 `rs2` 的低 16 位 |
| `sw rs2, offset(rs1)` | 写入 `rs2` 的 32 位 |

RV32I 本身要求自然对齐的访问必须得到支持。未对齐访问是否由硬件直接完成取决于具体执行环境，不能假定其代价或行为与对齐访问相同。

### 分支与跳转

条件分支直接比较两个寄存器，不依赖条件码。

| 分支指令 | 跳转条件 |
| --- | --- |
| `beq rs1, rs2, offset` | `rs1 == rs2` |
| `bne rs1, rs2, offset` | `rs1 != rs2` |
| `blt rs1, rs2, offset` | 有符号 `rs1 < rs2` |
| `bge rs1, rs2, offset` | 有符号 `rs1 >= rs2` |
| `bltu rs1, rs2, offset` | 无符号 `rs1 < rs2` |
| `bgeu rs1, rs2, offset` | 无符号 `rs1 >= rs2` |

分支目标为 `pc + sign_extend(offset)`。B 型立即数省略恒为 0 的最低位，因此只能表示偶数字节偏移。这也为包含 16 位压缩指令的实现保留了兼容性，但压缩指令不属于 RV32I。

| 跳转指令 | 操作 |
| --- | --- |
| `jal rd, offset` | `rd = pc + 4`，然后跳转到 `pc + sign_extend(offset)` |
| `jalr rd, offset(rs1)` | `rd = pc + 4`，然后跳转到 `(rs1 + sign_extend(offset)) & ~1` |

直接调用通常写作 `jal ra, function`。间接调用可写作 `jalr ra, 0(t0)`。将目的寄存器设为 `x0` 会丢弃返回地址，因此 `jal x0, label` 可用作无条件跳转，`jalr x0, 0(ra)` 可用作函数返回。

### 内存顺序

`fence pred, succ` 约束当前 hart 的设备 I/O 和内存访问顺序。`pred` 描述 fence 之前的操作集合，`succ` 描述 fence 之后的操作集合。

| 标记 | 操作类型 |
| --- | --- |
| `I` | 设备输入 |
| `O` | 设备输出 |
| `R` | 内存读取 |
| `W` | 内存写入 |

其他 hart、设备或协处理器不能观察到 `succ` 集合中的操作先于 `pred` 集合中的操作发生。`fence rw, rw` 为普通内存读写建立完整顺序。具体可见性仍由 RISC-V 弱内存顺序模型定义。`fence.tso` 使用 `fence` 的一种特定编码，它不是额外增加的第 41 条 RV32I 指令。

取指同步指令 `fence.i` 属于 `Zifencei` 扩展，不属于当前 RV32I 基础集。

### 环境调用与断点

| 指令 | 操作 |
| --- | --- |
| `ecall` | 向执行环境发起服务请求并产生精确陷阱 |
| `ebreak` | 把控制权交给调试环境并产生断点陷阱 |

`ecall` 的参数约定和实际服务由 ABI 与执行环境决定。`ebreak` 常由调试器用于实现软件断点。两条指令本身不指定陷阱处理流程，相关行为由执行环境和特权架构定义。

以上各类共包含 40 条 RV32I 指令。六条 CSR 访问指令和 `fence.i` 均属于独立扩展，不计入这 40 条指令。

## 函数调用

前八个整型参数放在 `a0`～`a7`，多余参数放在栈上。最多两个寄存器宽度的返回值放在 `a0`、`a1`。典型函数只保存自己会修改的 callee-saved 寄存器，并在需要继续调用其他函数时保存 `ra`：

```asm
sum:
    addi sp, sp, -16
    sw   ra, 12(sp)
    sw   s0, 8(sp)

    add  s0, a0, a1
    mv   a0, s0

    lw   s0, 8(sp)
    lw   ra, 12(sp)
    addi sp, sp, 16
    ret
```

叶函数如果不破坏 callee-saved 寄存器，往往不需要栈帧。是否使用 `s0` 作为帧指针也由编译选项和函数需求决定，并非每个函数都必须如此。

## 伪指令

伪指令由汇编器展开，不会引入新的机器指令。例如：

| 伪指令 | 一种常见展开 | 含义 |
| --- | --- | --- |
| `nop` | `addi x0, x0, 0` | 不产生可见效果 |
| `mv rd, rs` | `addi rd, rs, 0` | 复制寄存器 |
| `not rd, rs` | `xori rd, rs, -1` | 按位取反 |
| `neg rd, rs` | `sub rd, x0, rs` | 取负 |
| `j label` | `jal x0, label` | 无条件跳转 |
| `ret` | `jalr x0, 0(ra)` | 从函数返回 |
| `li rd, imm` | 一条或多条指令 | 装入常量 |
| `la rd, symbol` | 与位置和重定位相关的序列 | 取得符号地址 |

`li`、`la` 的具体展开取决于常量、代码模型和重定位信息，不能把它们固定理解成某一条基础指令。

## 注释

RISC-V 汇编使用 `#` 表示注释：

```asm
add x1, x2, x3  # x1 = x2 + x3
```
